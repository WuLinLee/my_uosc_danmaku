# uosc_danmaku：mpv 弹幕增强补丁

本仓库为现有 \`uosc_danmaku\` 脚本提供一组模块更新和配置覆盖，重点改进弹幕样式菜单、设置持久化、滚动轨道布局、智能密度筛选、重复弹幕合并、屏蔽词管理及加载诊断。

> **注意：这不是一份完整的 mpv 配置包，也不是可独立运行的弹幕插件。** 仓库只包含 4 个模块文件和 2 个配置文件；它们依赖你已有的、与这些模块接口兼容的完整 \`uosc_danmaku\` 安装。请勿把本仓库当作完整的 \`portable_config\` 直接替换使用。

这两个文件已加入仓库的忽略规则，更新模块时应保留本机已有文件。

## 前置条件

1. 已有可正常工作的 mpv 和完整的 \`uosc_danmaku\` 插件安装。本仓库没有包含插件入口脚本、其他模块、字典文件或上游工具函数；其中的模块会调用主脚本初始化的全局函数和数据。
2. 建议同时安装并启用 uosc，以使用完整的图形菜单和控制栏快捷按钮。菜单代码也保留了 \`mp.input\` 回退路径，但 \`uosc.conf\` 中的控制栏按钮只对 uosc 生效。
3. 使用与现有插件版本相匹配的模块。不要只把这 4 个文件放进一个空的 mpv 配置目录后期待插件独立启动。

## 安装与更新

先备份当前配置，尤其是已有的 \`modules\` 文件和两个 \`.conf\` 文件。

将仓库的 \`portable_config/\` **内部内容**复制到 mpv 实际使用的配置目录，保留相对路径。目标结构应类似：

\`\`\`text
<mpv-config>/
├─ scripts/
│  └─ uosc_danmaku/
│     └─ modules/
│        ├─ menu.lua
│        ├─ options.lua
│        ├─ parse.lua
│        └─ style.lua
└─ script-opts/
   ├─ uosc_danmaku.conf
   └─ uosc.conf
\`\`\`

其中 \`<mpv-config>\` 指 mpv 当前实际读取的配置目录；便携版通常是 mpv 程序目录下的 \`portable_config\`，其他安装方式则使用其对应的 mpv 配置目录。不要把仓库中的 \`portable_config\` 再套一层复制成 \`portable_config/portable_config\`。

### 配置文件合并

- **\`uosc_danmaku.conf\`**：本仓库只显式设置以下 4 项。若你已有同名文件，请保留自己的其他设置，将需要的键合并进去，并避免同一个键重复定义。

  \`\`\`ini
  autoload_for_url=yes
  render_mode=ass
  vf_fps=yes
  history_path=~~/_cache/danmaku-history.json
  \`\`\`

- **\`uosc.conf\`**：若你没有自己的 uosc 配置，可参考仓库文件使用完整的 \`controls=\` 行。若已有 \`uosc.conf\`，不要直接用本仓库文件覆盖它，也不要保留两条互相冲突的 \`controls=\`；请把 \`button:danmaku_menu\` 合并进原有 controls 列表。仓库示例将按钮放在章节按钮后面：

  \`\`\`ini
  controls=menu,ST-stats_tog,ST-thumb_tog,gap,play_pause,gap,subtitles,audio,<has_chapter>chapters,button:danmaku_menu,<has_many_edition>editions,<has_many_video>video,<stream>stream-quality,gap,space,speed,space,shuffle,loop-playlist,loop-file,gap,prev,items,next,gap,fullscreen
  \`\`\`

- **4 个 Lua 模块**：作为一组更新，分别覆盖目标目录中的同名文件。不要删除其他插件模块或主脚本。

复制完成后重启 mpv，使脚本和配置重新加载。打开「弹幕设置」总菜单，再进入「弹幕样式」即可查看设置。

## 菜单入口与设置项

使用 uosc 时，控制栏中的「弹幕设置」按钮会打开插件总菜单；选择「弹幕样式」进入统一设置页。菜单修改会立即作用于当前播放，只有执行底部的保存动作才会写入跨进程 JSON。

样式菜单当前提供以下项目：

| 菜单项目 | 可设置范围 / 选项 | 代码默认值 | 说明 |
| --- | --- | --- | --- |
| 粗体 | \`false\` / \`true\` | \`true\` | 切换字体粗体 |
| 大小 | 1–500 | \`55\` | 弹幕字号 |
| 描边 | 0–4 | \`1\` | 字体描边 |
| 阴影 | 0–20 | \`0\` | 字体阴影 |
| 速度 | 1–120 秒 | \`10\` | 滚动弹幕的显示时长；数值越大，滚动越慢 |
| 透明度 | 0–1 | \`0.70\` | 0 为全透明，1 为不透明 |
| 弹幕显示范围 | 0–1 | \`0.8\` | 弹幕布局可使用的画面高度比例 |
| 直播帧率 | \`auto\` / \`60\` / \`80\` / \`120\` / \`display\` | \`auto\` | 直播弹幕帧率模式 |
| 智能弹幕密度 | 0–100 | \`50\` | 100 完全跳过智能密度筛选 |
| 弹幕行间距 | 1.0–2.0 | \`1.2\` | 轨道高度相对字号的倍数 |
| 均匀分布弹幕轨道 | 开 / 关 | 开 | 开启时优先使用靠近布局中心的安全轨道 |
| 重复弹幕合并间隔 | -1–30 秒 | \`-1\` | -1 关闭；0 只合并时间戳相同的重复内容 |
| 同屏弹幕上限 | 0–500 | \`0\` | 0 不限制同时显示数量 |
| 跨颜色/类型合并重复弹幕 | 开 / 关 | 关 | 允许相同文字跨颜色和类型合并 |
| 屏蔽词过滤 | 开 / 关 | 开 | 整体启用或暂停两类屏蔽规则 |
| 管理屏蔽词规则 | 打开子菜单 | — | 添加、查看和删除菜单维护的规则 |

补充说明：

- 默认字体名为 \`Source Han Sans\`，但字体名称没有单独的菜单项目；需要更换时，可在 \`uosc_danmaku.conf\` 中显式设置 \`fontname=字体名\`。系统需安装对应字体。
- 固定在顶部或底部的弹幕默认显示时长为 5 秒（脚本选项 \`fixtime\`）；样式菜单中的「速度」调整的是滚动弹幕的 \`scrolltime\`。
- \`displayarea\` 的有效设置范围为 0–1。布局计算会至少保留一行字号高度，因此设为 0 并不等于彻底关闭弹幕显示。
- 若用户在 \`.conf\` 中显式设置某个样式键，该值会成为清除 JSON 后恢复的基准；未显式覆盖的项目使用上表的代码默认值。

## 设置保存、加载与重置

样式和过滤设置共用一份 JSON 文件，默认路径为：

\`\`\`text
<mpv-config>/script-opts/uosc_danmaku_style.json
\`\`\`

也可通过脚本选项 \`style_path\` 指定其他路径。

### 启动时的优先级

脚本先读取 \`uosc_danmaku.conf\` 和命令行选项，再加载 JSON。对于 JSON 中存在且通过校验的字段，JSON 值优先。因此优先级为：

\`\`\`text
有效的 uosc_danmaku_style.json
        ↓ 覆盖
uosc_danmaku.conf / 命令行显式设置
        ↓ 覆盖
options.lua 中的 DANMAKU_STYLE_DEFAULTS
\`\`\`

JSON 中缺失或无效的字段不会覆盖当前基础值。样式默认值集中维护在 \`options.lua\` 的 \`DANMAKU_STYLE_DEFAULTS\` 表中，\`uosc_danmaku.conf\` 不重复声明这些默认值，只保留需要覆盖的选项。

### 保存与清除

- **保存当前样式和过滤设置**：将当前整组样式/过滤状态写入 JSON，而不只是保存本次改动的单个项目。保存内容包括字体、字号、粗体、描边、阴影、滚动时长、透明度、显示范围、密度、轨道间距、重复合并、同屏上限、屏蔽词开关及直播帧率模式等。
- **清除已保存样式和过滤设置**：删除 JSON，并立即把当前运行中的设置恢复为启动时读取 \`.conf\`/命令行选项后的基础值；同时刷新当前弹幕和相关帧率滤镜。菜单中的单项「恢复默认值」基准也会更新为清除后的基础值。
- 保存失败时，菜单会显示具体错误信息；常见原因是目标目录不存在或没有写入权限。

例如，若旧 JSON 中保存了 \`merge_tolerance=2\`，即使代码默认值已经改为 \`-1\`，启动时仍会继续使用 JSON 里的有效值。想只关闭重复合并并保留其他个人设置，应在菜单把「重复弹幕合并间隔」改为 \`-1\`，然后保存；不要为了这一项清除整份 JSON。

## 布局与智能密度

### 滚动轨道

- 弹幕只在 \`displayarea\` 指定的高度范围内排布。
- 开启「均匀分布弹幕轨道」时，先从尚未使用过的安全轨道中选择靠近布局中心的位置；空轨道用完后，再优先复用最久未使用的安全轨道。关闭时则按从上到下的顺序寻找可用轨道。
- 碰撞检查根据该轨道上一条弹幕的出现时间、文字宽度和移动速度估算是否可能追尾，不遍历整条屏幕内的历史弹幕队列。
- 「弹幕行间距」控制轨道高度，约等于字号乘以行间距系数。例如字号 55、行间距 1.2 时，轨道高度约为 66 像素。行间距越大，可用轨道越少。

插件不会为了等待安全轨道而延迟弹幕播放。若当前没有可安全放置的轨道，该条弹幕可能被跳过；这与智能密度筛选导致的过滤是两个不同阶段。

### 智能密度

智能密度筛选发生在轨道分配之前：

- \`100\`：完全不执行智能密度筛选。
- 小于 \`100\`：在局部时间窗口内估算弹幕视觉占用，并参考文字的信息量、字符重复程度等因素，降低拥挤区域中部分弹幕的显示概率。
- 数值越低，筛选通常越积极；它不是“保留百分之多少弹幕”的固定比例，也不保证每个时间窗口留下相同数量。

如果密度较低时出现横向时间空档，而调到 100 后弹幕变得连续，说明部分弹幕在轨道分配之前已经被密度算法筛掉；轨道布局不会把它们补回来。

### 同屏弹幕上限

\`max_screen_danmaku\` 控制同一时间段内允许同时显示的数量，不是整集弹幕总数限制。它在智能密度筛选之后执行；超过上限时，会依据弹幕预计结束时间筛选，尽量保留显示时长较短的项目。设为 0 时不启用该限制。

## 重复弹幕合并

「重复弹幕合并间隔」与「同屏弹幕上限」是两个独立功能，不会互相修改对方的设置。

| 合并间隔 | 行为 |
| --- | --- |
| \`-1\` | 关闭重复弹幕合并（默认） |
| \`0\` | 只合并时间戳完全相同的重复内容 |
| 大于 \`0\` | 将与该组第一条弹幕的时间差不超过设定秒数的重复内容合并 |

合并规则：

1. 只处理从右向左滚动的弹幕，即类型 1–3。顶部固定弹幕（类型 5）和底部固定弹幕（类型 4）不参与合并，保留原有固定弹幕轨道行为。
2. 默认要求原始文字相同、弹幕类型相同，且颜色距离处于代码设定的容差范围（15）内。打开「跨颜色/类型合并重复弹幕」后，同样文字可以跨颜色和类型进入同一组。
3. 时间窗口以组内最早一条弹幕为锚点，不采用逐条向后累加的链式窗口；因此不会因为一串相邻时间差都很小，就无限延长同一组。
4. 合并组使用最早成员的时间戳，合并结果仍作为普通滚动弹幕从右向左飘过。其他独立弹幕不会为了等待合并窗口而延迟。
5. 合并组按数量统一高亮，不追加感叹号，也不显示 \`xN\`：

| 合并数量 | 字号倍率 | 高亮颜色 |
| --- | ---: | --- |
| 2–3 条 | 1.0 倍（不放大） | 青绿 |
| 4–6 条 | 1.1 倍 | 鲜蓝 |
| 7–10 条 | 1.2 倍 | 金黄 |
| 11 条及以上 | 1.3 倍 | 橙红 |

此功能用于预加载的普通视频弹幕。直播实时弹幕不会等待该时间窗口，也不会通过这项功能聚合。

## 屏蔽词与弹幕源屏蔽

插件同时读取两类文字屏蔽规则，并将它们合并使用：

| 来源 | 默认路径 / 配置项 | 管理方式 |
| --- | --- | --- |
| 原有外部规则文件 | \`blacklist_path\` | 保留原配置；支持 XML、JSON、TXT |
| 菜单维护的规则文件 | \`~~/script-opts/uosc_danmaku_blacklist.txt\` | 在「管理屏蔽词规则」菜单中添加或删除 |

菜单维护的 TXT 文件每行一条规则，默认位于 mpv 配置目录的 \`script-opts\` 下。该文件由菜单写入；修改后会重新加载屏蔽规则并刷新弹幕。菜单规则不会覆盖原有 \`blacklist_path\` 文件。

规则使用 Lua 的 pattern 语法，不是 PCRE 正则表达式：

- 普通文字（不含 Lua pattern 元字符）按字面子串查找。
- 含有 Lua pattern 元字符的规则按 Lua pattern 匹配。
- 无效的 Lua pattern 不会作为有效规则参与匹配。

「屏蔽词过滤」开关会整体启用或暂停两类文字规则。暂停时不会删除规则文件或规则内容。

「从源添加弹幕」菜单中的屏蔽动作则是屏蔽或解除屏蔽**整个弹幕源**，并非按弹幕文字过滤；两者互不替代。

## 直播弹幕

直播弹幕使用独立的实时事件生成路径。当前代码会在实时弹幕路径中应用屏蔽词、智能密度和滚动轨道分配，但不会执行预加载弹幕的重复合并，也不会执行普通视频的同屏弹幕上限算法。

「直播帧率」支持 \`auto\`、\`60\`、\`80\`、\`120\`、\`display\` 五种模式，默认 \`auto\`。本仓库的 \`uosc_danmaku.conf\` 同时启用了 \`vf_fps=yes\`；实际帧率滤镜效果仍取决于 mpv 当前视频、显示设备和主脚本的滤镜同步逻辑。

## 性能日志

将 mpv 日志级别调到 verbose 后，可在日志中查找以下标记：

- \`[danmaku load]\`：记录 XML/JSON 解析、各来源筛选与排序、合并来源时间线、重复弹幕聚合、密度/同屏限制、轨道布局和事件生成等阶段的耗时。
- \`[danmaku request]\`：记录弹幕匹配、剧集列表和弹幕内容请求的开始/完成时间、请求类型、结果状态及响应字节数。

这些日志用于区分网络等待和本地解析/布局耗时；它们不是播放性能测试报告。

当前实现还包含若干加载路径优化：已按时间排序的数据仅在检测到乱序时才排序；弹幕文字宽度、简繁转换和密度信息评分使用有界缓存；普通屏蔽词使用纯文本查找，复杂规则继续走 Lua pattern 匹配。

## 功能边界与验证

以下能力目前不属于本仓库实现范围：

- 根据“相似意思”而非完全相同文字自动折叠评论。
- 白名单优先级规则。
- 合并评论组的展开/收起交互。
- 为等待重复合并窗口或等待空闲轨道而延迟弹幕播放。

智能密度算法是面向 LuaJIT 的适配实现，不是浏览器版算法的完整逐字节等价移植，也不执行完整 Unicode NFKC 规范化。

本 README 根据仓库当前的 4 个 Lua 模块和 2 个配置文件核对整理；此处没有启动真实 mpv/uosc 环境进行播放验证。更新后请在自己的环境中检查菜单操作、弹幕显示、直播刷新、控制栏按钮及 mpv 日志。
